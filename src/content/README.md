# How to Create a New Blog Post

This guide explains how to create and publish blog posts in this SvelteKit blog.

## Quick Start

Each blog post lives in its own folder inside `posts/`. The folder name becomes the URL slug.

```bash
# Example: Creating a post that will be available at /blog/my-awesome-post
cd src/content/posts
mkdir my-awesome-post
cd my-awesome-post
```

## Step 1: Create the `index.md` File

Create an `index.md` file inside your post folder with the following structure:

````markdown
---
title: "My Awesome Post Title"
date: "2026-02-13"
description: "A brief description for SEO and post previews"
tags: ["technology", "tutorial", "webdev"]
category: "Technology"
canonical: "https://blog.navadeepnaidu.com/blog/my-awesome-post"
draft: false
image: "/og-image.png"
---
````

## Step 2: Frontmatter Fields Explained

| Field         | Required | Description                                | Example                                           |
| ------------- | -------- | ------------------------------------------ | ------------------------------------------------- |
| `title`       | Yes      | Post title shown in headings and meta tags | `"Understanding JavaScript Closures"`             |
| `date`        | Yes      | Publication date (YYYY-MM-DD format)       | `"2026-02-13"`                                    |
| `description` | Yes      | Brief summary for SEO and preview cards    | `"A deep dive into how closures work..."`         |
| `tags`        | Yes      | Array of tags for categorization           | `["javascript", "tutorial"]`                      |
| `category`    | Yes      | Single category for the post               | `"Technology"` or `"Personal"`                    |
| `canonical`   | Yes      | Canonical URL (use your blog URL)          | `"https://blog.navadeepnaidu.com/blog/post-slug"` |
| `draft`       | No       | Set to `true` to hide from production      | `false` (default) or `true`                       |
| `image`       | No       | OG image for social media previews         | `"/images/post-cover.png"`                        |

## Step 3: Add Images (Optional)

If your post has images, place them in the same folder as `index.md`:

```
my-awesome-post/
├── index.md
├── diagram.png
├── screenshot.jpg
└── chart.webp
```

Reference them in your markdown using relative paths:

```markdown
![Architecture diagram](./diagram.png)
![Screenshot of the app](./screenshot.jpg)
```

**How it works:** The build script (`scripts/copy-post-images.js`) automatically copies these images to `static/content/posts/my-awesome-post/` during build, and the remark plugin transforms the relative paths to absolute URLs.

## Step 4: Preview Your Post

```bash
npm run dev
```

Visit `http://localhost:5173/blog/my-awesome-post` to see your post.

**Note:** Draft posts (`draft: true`) will only show in development mode, not in production builds.

## Step 5: Build and Deploy

```bash
# Build the static site
npm run build

# Preview the production build locally
npm run preview
```

The build process will:

1. Copy all images from post folders to `static/content/posts/`
2. Transform markdown to HTML with syntax highlighting
3. Generate RSS feed at `/rss.xml`
4. Generate sitemap at `/sitemap.xml`
5. Create static pages for all routes

## Best Practices

1. **Use descriptive slugs** - Folder names should be URL-friendly and descriptive
2. **Write good descriptions** - They appear in search results and social shares
3. **Use appropriate tags** - Help readers discover related content
4. **Optimize images** - Use WebP format when possible, compress images
5. **Test drafts locally** - Use `draft: true` while working on posts
6. **Check canonical URLs** - Ensure they point to your blog domain
7. **Preview before deploying** - Always run `npm run build` and `npm run preview` locally

## Troubleshooting

**Images not showing?**

- Check that images are in the same folder as `index.md`
- Use relative paths starting with `./`
- Run `npm run copy-images` manually to test

**Post not appearing?**

- Check if `draft: true` is set in frontmatter
- Verify the folder structure is correct
- Ensure `index.md` exists in the post folder

**Build errors?**

- Validate frontmatter YAML syntax
- Check for missing required fields
- Ensure dates are in YYYY-MM-DD format
